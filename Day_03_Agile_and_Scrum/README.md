# Set 1 -Grocery Ordering and Home-Delivery Application – Jira Scrum Backlog

## Project Overview

This project focuses on managing the development of a Grocery Ordering and Home-Delivery Application using Jira Scrum.

The Product Backlog was organised into epics and user stories. MoSCoW prioritisation and Fibonacci story point estimation were used to organise and estimate the work.

## Project Details

- **Project Name:** Grocery Ordering and Home-Delivery Application
- **Project Key:** GOHDA
- **Project Type:** Scrum
- **Total Epics:** 3
- **Total User Stories:** 12
- **Sprint:** GOHDA Sprint 1
- **Total Story Points:** 41

## Epics

### 1. Browse and Search
- Browse grocery categories.
- Search grocery products.
- View product details and prices.
- Filter products by category and price.

### 2. Cart and Checkout
- Add products to shopping cart.
- Update product quantities.
- Make secure UPI payments.
- Receive order confirmation.

### 3. Delivery Tracking
- Select delivery time slots.
- Track grocery order status.
- Receive delivery notifications.
- View previous order history.

## Sprint and Board Management

A Scrum sprint named GOHDA Sprint 1 was created to organise the selected user stories.

The Jira Scrum Board uses three workflow columns:

- **To Do:** Work that has not started.
- **In Progress:** Work currently being developed.
- **Done:** Work that has been completed and meets the Definition of Done.

## Definition of Ready (DoR)

A story should have a clear description, acceptance criteria, identified dependencies, an estimate, and a priority before development begins.

## Definition of Done (DoD)

A story is complete when its acceptance criteria are satisfied, development and code review are completed, required tests pass, critical defects are resolved, and the Product Owner accepts the work.
